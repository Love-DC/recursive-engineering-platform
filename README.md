## Prototype safety boundary

The SQL under `db/prototype` remains a trusted single-Owner prototype, not a production migration or authorization interface. For an isolated, non-production Supabase A0 pilot, use the compatibility bootstrap and ordered install path in [`db/supabase/README.md`](db/supabase/README.md); do not apply the raw prototype chain directly to a hosted Supabase project. The registration prototype uses a trusted single-Owner test boundary; caller-supplied `project_id` is routing data, not proof of project authorization. The identity key is treated as already normalized by its caller; the database enforces exact equality for the supplied identity version.

The Stage 1B tables model project/resource grants, execution attempts, resource claims, dependency graph membership, OwnerDecision provenance, evidence, and external operation receipts. The Stage 2A/2B prototype protocols are implemented and tested in disposable PostgreSQL CI. Stage 3 delivery and external-operation reconciliation are implemented, independently reviewed, merged, and post-merge verified in PR #49 for the disposable PostgreSQL 17.12 prototype only. T12/T13/T14/T15/T21/T22 passed the Stage 3 protocol suite; exact candidate and merge evidence is recorded above. The connected GitHub session surface still does not provide an independently authenticated native-approval principal, and Deployment is explicitly unsupported. Remaining unimplemented areas include path-overlap resource locking (T06 PARTIAL) and authenticated production project authorization. Bounded discovery/decomposition (T19/T20) is now implemented and tested for the disposable prototype. T25 is PASS for the tested disposable prototype: candidate HEAD `4fcb5bc5feea0142fb4a4b5bf28bc99a1bc34b76`, exact-head [Run #199](https://github.com/Love-DC/recursive-engineering-platform/actions/runs/45956571676), independent review [PASS](https://github.com/Love-DC/recursive-engineering-platform/pull/81#pullrequestreview-6084735569), squash merge `a303618092ba0c762c8f850603b9c57328b00035`, and exact-merge [Run #200](https://github.com/Love-DC/recursive-engineering-platform/actions/runs/45958199427) all verified. The Resource trigger protects against ordinary runtime-role DELETE operations, but this is not an invariant against a privileged database administrator: a PostgreSQL superuser or sufficiently privileged schema/table owner can deliberately disable triggers or alter the schema. The trusted single-Owner prototype does not defend against a hostile database administrator. Only the isolated non-production Supabase candidate used for the A0 pilot was changed; the retired RAE Supabase project was not accessed or modified. The old RAE system remains separate and unchanged.
