## Stage 4B — transaction isolation contract

The authorization gate uses MVCC reads while holding Resource/Project advisory locks to avoid the previously identified tuple/advisory lock inversion. Accordingly, all public Context RPCs must reject transactions whose `transaction_isolation` is not `read committed` (SQLSTATE `25001`) before lock acquisition or authorization-row reads. The Stage 4B regression establishes a REPEATABLE READ snapshot with a harmless query, then verifies rejection by source revision recording, Context Pack compilation and Context Pack retrieval. An explicit READ COMMITTED cache-fetch control must still return `ready`. This is prototype transaction-contract evidence; it does not change T17/T18's PARTIAL production-authorization status.
